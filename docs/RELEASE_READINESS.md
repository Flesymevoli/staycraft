# 受控预览部署验收记录

更新：2026-10-23。当前前两项核心功能的自家数据基础版本已完成代码与本机验收，尚未公开部署。模型真实接口、正式启用和线上Auth验收仍未完成，详见TODO的A1–A4。

## 实际验证范围

- Node.js 24、Next.js 16.4.2、Playwright 1.62.1，依赖版本由lockfile固定；npm ci重装、lint、类型检查和生产构建通过。
- npm run release:check包含27项隔离检查；覆盖资料/图片/房型复用、账号隔离、订单/会话详情、房态/清洁撤销、入住退房/取消审核、关联待办、自动回复与接管、正式营业额、预订金额、经营助手和实际处理记录。
- 覆盖中英文、320/390/658/1280宽度、加载/空/失败/冲突及恢复。关键手机截图已检查；未采用未跟踪的桌面样式草稿。
- SQL回滚夹具验证权限、跨账号/客人隔离、幂等、敏感请求保护、并发资料/开关变化、金额分摊和事务审计。全部使用虚构资料并回滚，未修改真实业务订单。
- 后端75项单元测试通过（Python3.12及已有.vendor）；它是可选旧草稿服务，不是当前核心链路依赖。
- 生产依赖审计0漏洞（本次扫描）；10张主要业务表RLS、受限RPC及私有room-photos已核对。安全顾问仅有既有Auth泄漏密码保护提醒。
- 当前远端15条迁移记录，新增自动回复、金额及操作审计迁移已应用；历史时间戳差异见supabase/README，不能盲目db push。

## 未被这些检查证明的事项

实际Vercel域名/HTTPS/真实Auth双账号未验收；本机隔离夹具不替代线上验收。正式模型/自动发送未开启，真实模型配置缺失，固定虚构资料的接口测试也尚未发出请求。市场外部来源、客人反馈评分及推广助手未完成，不以规则排序或已有图表冒充完整AI能力。

客人端仅作预订/消息来源，无真实付款退款、跨设备找回和完整商用反滥用。账号由管理员准备，无前端注册/找回密码。当前版本适合准备受保护预览，不代表面向陌生客人的完整商业平台。

## 复验与回退

在frontend运行npm run release:check，报告frontend/qa-release-report.json由Git忽略。付费模型脚本不在默认检查中。GitHub CI配置执行相同检查，不执行部署或SQL迁移。部署按DEPLOYMENT，回滚按ROLLBACK；代码回滚保留订单、图片与审计，数据库前向修复。
