# 本机经营端演示

这套样本复用当前经营端页面，只用于演示已经完成的客房、订单和日程。所有人物、地址与订单均为虚构，数据仅保存在独立进程内存中，不写云端，不调用AI，不接收付款，也不是课程提交文件。

## 打开

在已经完成构建的frontend目录运行npm run sample，再打开http://127.0.0.1:3106/login。

## 已准备的场景

| 场景 | 初始内容 | 可演示的操作 |
| --- | --- | --- |
| 房型复用 | 大床、双床、家庭房三种房型 | 添加客房时直接选择已有房型 |
| 客房状态 | 101/102/103/201/202启用，203停用；102与201待清洁 | 点击详情，编辑房号、清洁与启用状态 |
| 今日到店 | 101林小夏、201宋听澜 | 首页选择当天查看预计到店；确认不代表已办理入住 |
| 今日离店 | 103陈小舟 | 首页当天查看计划离店，不假造退房记录 |
| 已取消 | 102许知遥 | 工作台显示已取消；不会占用当日日程或预订房量 |
| 取消待审核 | 201宋听澜 | 展示待审核状态；本轮没有审批按钮或实际退款 |
| 明日到店 | 202周小雨 | 日历切换到明日查看安排 |

可按“首页日程 → 工作台客房/订单 → 点击102改为已清洁 → 回工作台 → 我的房型设置”演示。修改101房号后订单和日程显示新房号；订单金额是原价格快照。

房型图片可手动选传，上传仅进入演示内存；重启丢弃。没有预置照片，不把场景图片误当成真实民宿照片。示例数据源在frontend/scripts/operator-sample-data.cjs，使用稳定UUID与相对日期，不维护多份手工日程。

## 边界与复验

分析/探索、正式在线消息、AI处理、实际入住退房与取消审批仍保留未接入提示；这套样本不证明这些功能已经完成。旧/native-*与FastAPI/SQLite演示仍独立，不能拼接为同一条真实业务链。客人预订入口在本机样本中隐藏，避免与云端直订混淆。

演示仅监听127.0.0.1:3106；加载器拒绝托管环境，禁止向非本机或隔离后端目标发起fetch。正式构建没有导入该数据源，只有独立启动脚本预加载。不要把本机演示账号用于公开部署；以后线上演示需要单独安排受控样本账号与数据。

运行scripts/qa-operator-sample.cjs可验收登录、独立会话、日程过滤、改房号/清洁、保存冲突、重启恢复、退出和320/390/658/1280宽度。该测试验证真实页面与内存后端，不能冒充真实云端RLS或双账号浏览器验收。
