## 当时确认的设计方向

采用柔和版预览的视觉方向。主工作区近白（#fdfdfe），淡紫用于侧栏与外围（#ebe7f8 至 #f4f2fa）。正文近黑（#303039），交互强调用蓝紫（#6554c7），全局图表变量为柔紫（#7866d6），但最终原稿内联 SVG 实际使用 #6554e8，按原稿保留。图表周末点和仪表末端使用原稿亮黄 #ffdc32（不同于全局 --yellow/#e7d598）；黄色用于周末等已有数据标记，状态色只表达明确的业务状态。

| 项目 | 桌面适配基准 |
|---|---|
| 字体 | 中文 Noto Sans SC，核心数字 Outfit。正文 400，普通标题 500，关键结论可用 600。中文标题用正常字距 |
| 字号 | 首页招呼语 34px（窄窗 30px），其余页面标题 26–28px，卡片标题 16px，正文 14px，辅助文字 12–13px，核心数字 28–32px。数字表格右对齐 |
| 表面 | 白卡、细浅边框（#efedf3）、约 18px 圆角，阴影极轻。主要操作用实色，其余用文字或浅底，普通说明直接排字 |
| 布局 | 工作台以经营判断和优先行动为主，经营数据可并排放趋势图和明细，推广可并排放线索和编辑器。窄窗按阅读顺序改单列 |
| 顶栏 | 民宿名称保持单行，过长省略并保留完整名称。空间不足时搜索换行，更窄时账号区精简为头像 |
| 品牌 | 采用用户选定的对称屋檐版，保留原房屋宽度、四格窗、三根柱子、太阳与弧线。归档 PNG 是设计稿，正式替换前需分别制作横标与独立图标 |

演示方案归档：[原预览、柔和版、Noto 默认版及选定 Logo](../artifacts/staycraft-design-reference-20261111.zip)。当时选定的视觉参考为 `staycraft_fonts.html`，路径 `C:/Users/86299/AppData/Local/Temp/staycraft-gemini-review-4c21ebef30a34cc785008907840e7cd0/staycraft_fonts.html`。归档同名文件与原文件哈希一致；中文选项 3 Noto Sans SC。直接读取原 CSS 层叠、内联 SVG 与脚本，以实际生效样式为准。`frontend/src/components/desktop-design-tokens.css` 记录提取值及原文件 SHA-256。仪表沿用原 18 段几何，末两填充段黄色随实际占用率移动，黄色是末端强调，不新增业务阈值。预览内的数据与动作是示意，桌面适配复用现有经营指标、权限和真实工作流。正式端使用完整中文字体资源，不能直接复用预览的字符子集。线上共享演示保持现行版本，桌面从独立本地入口验证。

## 桌面首页已确认交互
- 招呼语为「你好，显示名」，无姓名回退「你好，店主」。显示名仅用于文字展示，不参与权限。
- 核心判断中的同年日期用 MM.DD-MM.DD，跨年保留年份；记录中的原始日期不改。
- 首页最多展示两类不同机会，同类沿用服务端优先顺序第一条；全为缺失指标的项不用于补位。原 ID、业务日期和全部机会数据保留。
- 诊断在来源上面，数据与分析记录集中放在来源下面可展开，右栏仍是计划与助手。
- 采集提示不常驻：仅确认当前日期没有报价时显示，180ms 透明度过渡，6 秒自动消失；鼠标悬停或焦点停留暂停，支持关闭。同一工作区挂载期间同日期不重复；减少动态效果时直接切换。错误或加载中不能视为缺数据。

## 旧运行版本记录
- 中性近白背景、近黑文字/主按钮、蓝紫强调，亮黄少量语义点缀。
- 平面卡片、细边框，无阴影、高光、凸起按钮和卡片磨砂；导航允许半透明毛玻璃。
- 外卡约16px，按钮/分段更圆，可胶囊999px。不要卡片很圆而按钮方硬。
- Logo文字近黑，房屋/柱形蓝紫；星光、四格窗、底部弧线亮黄。禁止整图黑白滤镜。
- PC是真正侧栏工作台，手机为触控/阅读布局；禁止把430px手机壳作为PC方案。

## 信息层级与行为
- 工作台：收入概况→身份/时间/状态→核心判断→关键依据→前1–2项优先决策→原位全文→历史。
- 判断是经营结论，避免重复KPI和长数字串；动作标题+短原因，详细论证在全文。
- 问问 AI 复用当前经营周期；按现有指标展示对应主题，数据足够时省略重复的预订概况问题；有已知空房才推荐空房，有已订记录才推荐繁忙日期，有金额才推荐已订金额。快捷问题不覆盖输入草稿。同一周期同主题复用回答并定位，已回答主题退出推荐区，候补问题依次补位；鼠标展开及新回答用短动效，键盘和减少动态效果时即时反馈。回答按顺序保留，失败保留输入并提供重试；Escape 收起。
- 展开/收起保留URL、不重新调用模型；历史原文不悄悄改写。
- 数据页：筛选/日期/标签从属指标与图表，不能占据巨大首屏。
- 市场页：按用户11/11最新要求，默认一个入住日期、当日统计与各店报价，报价列表上方用七日中位数折线图比较入住日；来源详情原页展开。取消旧五家名单替换/移除/整批更换及人工核对。切换日期立即隐藏旧结果；无报价显示真实空态，不回退虚构报价。重点是价格，覆盖/条件/范围说明次级或折叠，不堆叠小KPI卡。报价样本不能称全市场，无历史不画涨跌。
- 调价建议放在当日统计下方，突出一句价格位置判断与一段操作建议。沿用蓝紫浅底、平面边框。
- 携程列表起价合并到当日住宿报价。列表随页面自然排列。
- 桌面端在周边住宿报价卡右上角打开「实时采集」。网页演示只显示一行小字提示。
- 推广提供固定模板、结合线索、编辑保存和草稿重开。最近活动在页面顶部，与天气共用筛选栏。天气以民宿地址为中心，活动仅显示有结果的分类。文案区显示本次选中的一条活动或天气，换选即替换，刷新后重新选择。
- 我的及五项导航保留。不要为简化删除保存、编辑、重试等必要操作。

## 图表与动效
数据线/选择态蓝紫，周末亮黄，网格低对比；单位、期间、缺失值明确。保留选点、图例、键盘/触控与明细，不新增青色选中滑条/指标卡底部强调横条。单次报价不画趋势。
工作台只做轻反馈，尊重减少动态效果；不对经营数字反复播放装饰动画。宣传可有滚动交互，手机自然流及低高度/减少动态回退。
