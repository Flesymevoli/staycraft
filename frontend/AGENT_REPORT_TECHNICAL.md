# 收入诊断报告链路（本地验收版，2026-11-05）

本轮复用现有 Agent Loop、模型封装、Supabase 权限和 RollingGo，不改全站架构。尚未部署。

## 调查与写作

1. 认证接口从登录用户确定民宿，读取当前指标与库存。模型自主选择 get_revenue、get_metrics、get_bookings、get_inventory、query_market。
2. get_revenue 分页读取完整已记录订单，由代码按住宿日分摊整数分金额，区分已完成、未来已订、历史未完成；提供日期、房型、渠道构成、同比长度周期比较、价量分解及占比。取消排除；不提供虚构收款、利润或退款金额。
3. 每次调查结果保存为带编号、周期、来源和时间的不可变证据快照。调查请求完成后，客户端发起同 runId 的写作请求。
4. 独立写作预算为 6000 tokens，修复轮 8000 tokens，最多三轮，总阶段预算 150 秒。优先已配置的官方 DeepSeek；调查保留课程接口及官方回退。所有密钥仅服务端读取。
5. 校验 JSON、字段路径、数值/单位、证据范围，再由独立模型请求复核统计周期、排名与因果表达。复核失败反馈具体问题，使用相同证据修复，不调用外部酒店工具。
6. 报告通过后才更新首页摘要；首页与详情使用同一报告。保留旧版结果兼容显示。

## 状态与恢复

沿用 decision_agent_runs 与 RLS。phase 区分 investigated、writing、writing_failed、complete；status 保留 completed、limited、failed。完整报告也可能因外部工具失败处于 limited，不更换标签掩盖失败。

调查与写作分别在 HTTP 请求内 await 完成，不依赖请求结束后的临时 Promise。JSON 结果保存快照、草稿、报告、步骤、token 用量和结束原因。失败后按 runId 续写；页面刷新读取任务进度；超时运行锁可回收。该机制不是无人值守队列：客户端中断后需要重新打开页面/重试继续，不能宣称后台一定自行跑完。

缓存按民宿、语言、周期、数据指纹隔离；并发运行受唯一约束保护。所有读写限定已认证民宿；工具无修改价格或发布推广权限。历史依据不随新资料改写。

本地 QA 使用隔离订单库与 tmp/sample-agent-runs-v2.json 持久化任务。该文件不是生产数据库。真实模型调用与只读酒店报价单独标识；演示订单不会写入云端经营记录。

## 验证范围

- qa-agent-revenue.cjs：13 组，跨期分摊、取消、缺值、历史可比性、价量变化、完整分页与占比。
- qa-agent-report.cjs：17 组，截断/超时重试、外部报价失败保留内部分析、缺历史不编趋势、摘要一致、字段/单位/空值验证、语义复核失败恢复。
- qa-decision-agent.cjs：23 组既有多轮工具选择、错误观察、权限、市场日期、缓存及推广动作证据测试。
- qa-operator-sample-data.cjs：7 组，基础样本不变、丰富样本多日期锚点一致性、无重复占房、渠道与 PostgreSQL fixture。
- qa-agent-store.cjs：本地 PGlite 持久化、并发与 RLS 隔离检查。不是托管数据库压力测试。

这些自动测试使用隔离夹具/模型 Mock。真实生成结果和页面验收另记录于 docs/SESSION_HANDOFF.md，不能用上述 Mock 冒充真实端到端成功。

## 当前边界

金额是已完成住宿对应的已记录房费，不是实收或净利润。历史库存缺失时不推算过去入住率。渠道记录不保证全渠道覆盖。外部报价是指定日期供应商起价，不是同房型市场均价或需求指数。模型复核降低误判风险，不保证消除所有推论错误。

OpenNext Cloudflare 构建已通过，未发布到生产验证长请求；构建器提示 Windows 兼容性和 Node middleware 支持仍有局限。发布前仍需在目标环境验收任务恢复与运行时限。
