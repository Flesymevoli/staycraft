# 柔白浅层 UI：可复现的风格范式

日期：2026-09-19  
状态：独立设计研究稿，待确认；不是当前原型的新基线。

本稿从用户提供的两张原始参考图提炼视觉规则，不复制其中的任务管理、课程成员或页面结构。不以此前 AI 生成的效果图作为证据。原型、`UI_STYLE.md`、现有五页功能和课程线框图均不因本文自动改变。

**用户最新澄清：图二主要作为颜色与小卡片样式的参考，图表形式不需要学习。** 曲线、渐变面积、浮标和坐标样式不属于本稿的复现要求。此前选定的图二导航方向单独保留。

**一句话定义：以接近白色的中性底色建立连续空间，用轻微明度差与浅阴影分层，用近黑色明确阅读和交互焦点；彩色只在局部承担氛围、状态或数据表达。**

“柔白浅层”是本稿的工作名称，不是已确认的行业分类。它有 Soft UI 的柔和层次，但无需复现强烈凹凸、厚玻璃或全局拟物效果。

## 1. 参考图分别提供什么

| 维度 | 图一：任务日历与表单 | 图二：成员趋势与导航 | 可迁移的规则 |
| --- | --- | --- | --- |
| 基底 | 上部带暖色、粉紫雾化色彩，下部回到浅灰白 | 主要为白与灰白，颜色集中于图表 | 页面底色安静；不要求每页都有粉紫渐变 |
| 表面 | 白色按钮、日期、输入面形成较明确的块面 | 大容器和分段控件通过很轻的明暗变化分层 | 用邻接明度、留白和浅阴影表达层级 |
| 深色 | 当前日期、筛选项、导航选中项和主按钮有深色实体 | 导航选中图标、选中文字、图表浮标为深色 | 深色优先承担焦点与当前状态 |
| 彩色 | 优先级、标签、动作以及顶部氛围 | 数据曲线与面积填充 | 氛围色、状态色、数据色需要分工 |
| 导航 | 有浅色容器，当前项有深色胶囊 | 图标与文字直接排列在底部，当前项实心黑色 | 本项目采用用户已选择的图二方向 |
| 排版 | 标题、时间、正文、说明形成多级对比 | 问候语偏重，大数值偏轻，说明偏灰 | 字重服务语义，不把所有大字都加粗 |

两张图不是同一套完整设计系统。图一提供页面氛围与圆润控件，图二提供小卡片的白灰层次、内部排版与颜色气质；导航按用户此前偏好采用图二。不要把图二整个展示面板按比例缩成手机页面。

## 2. 必须保留的六条视觉规律

1. **中性空间占主导。** 白、灰白、文字灰承担页面主体。彩色只在局部出现。去掉彩色后，页面仍应结构清楚。
2. **白色要有邻接差异。** 白表面靠浅灰底、间距和微弱投影被识别；不是靠一圈发光描边才能成立。
3. **圆润但有尺度。** 大内容面、输入框、小标签、圆形图标按钮使用不同的圆角类别，不能全部胶囊化。
4. **黑色是一种视觉权重。** 用在当前状态、重要文字和必要的主操作。多个黑色大按钮同时出现，会破坏安静感。
5. **层次来自排版先于容器。** 先靠对齐、距离、字号与字重建立信息组，再决定是否需要表面。
6. **颜色有明确归属。** 背景渐变营造氛围，图表渐变归属于数据，标签颜色表达状态；三者不能互相代替。

## 3. 参数的可信边界

- 可从参考图观察：颜色分布、形状类别、相对层次、导航选中逻辑、图表的线与填充分工。
- 不能仅凭截图确认：精确字体名称、字号、HEX 色值、阴影数值、真实透明度、是否使用背景模糊、交互动画和无障碍表现。
- 下文所有数值均为**供实现与调试使用的建议起点**，不是截图吸色或源文件测量结果。
- 图一有手机外壳，图二有展示背景。外壳的厚黑边、整个样机的外投影、图片四周的大留白，都不是应写进 App 的组件样式。
- 只推导浅色模式；暗色模式需要另外设计，不能简单反相。

## 4. 色彩分工与建议变量

| 角色 | 建议起点 | 使用规则 |
| --- | --- | --- |
| 页面底 | `#F1F2F3` | 连续的大面积中性空间 |
| 浅层底 | `#E9EBED` | 小范围托底、分段轨道；不作厚灰边框 |
| 内容面 | `#FCFCFD` | 比页面亮一点，允许接近纯白 |
| 输入/抬升面 | `#FFFFFF` | 表单输入或少量抬升控件 |
| 主文字 | `#202124` | 统一中性炭黑，不混蓝灰主标题 |
| 次文字 | `#61656D` | 说明、未选导航、辅助信息 |
| 第三级文字 | `#70757D` | 少量注释；不通过极浅灰制造精致感 |
| 强状态 | `#202124` + 白字 | 选中日期、必要主按钮、浮标 |
| 轻分隔 | `#DDE0E4` | 行列表、必要表单边界，少量使用 |
| 暖雾色 | `#F3DED2` | 局部背景氛围 |
| 粉雾色 | `#EAD9E5` | 氛围中过渡 |
| 紫雾色 | `#DFDAF1` | 局部背景或数据填充 |

### 背景配方

- 默认是中性底，不叠彩色。
- 需要柔和欢迎感时，仅在顶部加入两团宽而淡的暖色/紫色径向渐变；建议影响顶部约 240–340 CSS px，向下回到中性底。
- 一屏同时有彩色图表时，背景氛围进一步减弱；图二甚至可以完全不加彩色背景。
- 不把粉、紫、蓝设成全屏高饱和线性渐变；不在每张卡片里重复一份背景渐变。
- 对“中性占主导”的检查是视觉判断，不要求精确像素比例。可把 80% 以上非图像界面接近中性当作粗略起点。

### 状态配方

状态色用淡底 + 深色文字，例如成功 `#E4EDE6` / `#386348`、提醒 `#F4E8D5` / `#805B26`、需注意 `#F1DDE0` / `#8B424B`。必须配文字或图标，不能只凭颜色判断。紫色标签不自动等于“AI”，更不能在每个组件上出现。

## 5. 层次与材质：只建三层

| 层级 | 内容 | 建议表现 |
| --- | --- | --- |
| 0 · 页面 | 标题、开放式列表、导航 | 页面底，通常没有阴影 |
| 1 · 分组表面 | 必要的数据面、资料组、表单区 | 略亮表面；无阴影或非常轻的单层投影 |
| 2 · 当前操作 | 分段选中项、临时提示、浮层 | 白面或炭黑面；略清晰的接触阴影 |

建议阴影起点：普通表面 `0 6px 18px rgba(35,40,48,.035)`；小控件 `0 2px 6px rgba(35,40,48,.07)`。二者按需选择，不层层叠加。

图二可见边缘明暗形成的浅层次，但这不足以证明它是透明玻璃。复现时先用实色表面和轻阴影，不把 `backdrop-filter`、连续亮边或大面积内渐变设为默认。

图一的黑色按钮略有柔和边缘；可借用柔和轮廓，不照搬高亮凸面。尤其避免灰黑内阴影、环形白高光与厚重凸起同时出现。

**诊断：** 去掉所有阴影后，内容分组仍应可读；加回阴影后，只感到轻微前后关系，不应首先注意到光效。

## 6. 形状与间距

以 390 CSS px 宽手机为设计起点。参考图像的像素尺寸不是实际控件尺寸。

| 元素 | 建议尺寸/圆角 | 原则 |
| --- | --- | --- |
| 页面边距 | 20–24 px；窄屏 16–18 px | 主内容保持共同左边线 |
| 区块间隔 | 24–32 px | 比同组内部距离明显更大 |
| 组内间隔 | 8 / 12 / 16 px | 用距离说明关系 |
| 内容表面内边距 | 16–24 px | 先留文字空间，再确定表面高度 |
| 大分组表面 | 圆角 24–28 px | 不随内容高度无限放大 |
| 普通输入 | 高 48–52 px，圆角 18–24 px | 多行输入保持圆角矩形 |
| 标签/筛选项 | 可视高 30–36 px，胶囊形 | 交互热区至少 44 px 高 |
| 图标按钮 | 44–48 px，正圆 | 只用于短操作，不用于内容容器 |
| 普通列表行 | 60–72 px 起，随内容增长 | 不给每行套独立白卡 |
| 两列摘要间距 | 10–12 px | 内容放不下时改结构，不能无限缩字 |

复现时使用 4 px 间距体系。嵌套表面的圆角应协调：通常内层比外层小，并避免卡片套卡片套胶囊。文字变长时允许换行与增高，不以 `overflow:hidden` 掩盖内容。

## 7. 字体规则

两张图都偏向干净、圆润的无衬线，但无法确认是同一种字体。本项目若采用这套方向，可继续使用已随项目保存的 Outfit，中文配 PingFang SC / Microsoft YaHei；这属于可实现的近似方案，不宣称原图同款。

| 语义 | 起点 | 使用限制 |
| --- | --- | --- |
| 问候或编辑型大标题 | 30–36 / 500–600 / 1.12–1.2 | 一屏通常一个视觉主标题 |
| 主数据数字 | 40–48 / 350–450 / 1.0–1.1 | 像图二一样靠尺寸表达，不必粗黑 |
| 区块标题 | 19–22 / 500 / 1.3 | 和正文有明显层级 |
| 正文/输入 | 15–16 / 400 / 1.5–1.6 | 内容密时先缩文案 |
| 行标签/次级说明 | 12–13 / 400 / 1.45 | 仍须可读，避免浅灰小字堆积 |
| 导航标签 | 11–12 / 400，选中 600 | 一致基线，不挤压成不可读小字 |

字号/字重/颜色最多选择一到两种来突出同一个信息。不要所有标题、大数字、按钮都同时最大、最黑、最粗。英文大标题可少量负字距（约 -0.02em），中文正文不加负字距。

## 8. 导航采用图二的语法

已知用户偏好：图二的导航。其关键不是某几个图标，而是：

- 图标和文字直接排列于底部的中性空间，没有整条独立胶囊底座。
- 未选项：中灰线形图标 + 中灰常规标签。
- 选中项：近黑实心图标 + 近黑较重标签；不再在图标后加黑色圆圈或胶囊。
- 每项使用相等的布局单元。按图标中心等距，而不是按各图标实际轮廓的左右空白猜间距。
- 建议图标可视尺寸 23–26 px，图标与标签间距 5–6 px；含安全区前的导航高度约 64–72 px。
- 底部背景可不透明以保证滚动时可读，但应与页面融合；不要产生悬浮白药丸或强投影。
- 滚动内容必须留出导航高度和底部安全区；实心选中图标也要有 `aria-current` 等状态语义。

图二最右侧的大“＋”是独立新增操作，不是导航规律。本项目保留五个既有目的地 Home / Work / Analysis / Explore / My Homestay，不为相似外观凭空加“＋”。

“My Homestay”较长时，可以使用经过确认的短标签，或允许两行并让各项图标中心保持对齐；不要擅自改功能名称，也不要压缩所有标签。

## 9. 图二的小卡片语法

学习的是“一个轻薄的完整信息面”。拿掉图二的趋势图，标题、说明、重点信息和局部操作的关系仍然成立。卡片可以装经营建议、待处理事项或文件摘要，不限定为数据卡。

### 结构配方

1. 外层是略浅于页面的白灰表面，圆角柔和；边缘明暗很轻，先读到内容，再感到层次。
2. 标题、说明与主要内容使用共同内边距，不给每个字段再套白卡。
3. 顶部安排主题和可选的小操作；重点数字仅在内容需要时出现。
4. 中间只建立一个主要阅读焦点，保留必要留白。
5. 底部最多一个主要去向。说明卡没有操作时，不硬加按钮。

### 可复用的卡片比例

| 项目 | 普通卡片 | 约 160–180 px 宽的紧凑摘要卡 |
| --- | --- | --- |
| 内边距 | 20–24 px | 14–16 px |
| 圆角 | 24–28 px | 20–24 px |
| 标题到说明 | 6–8 px | 4–6 px |
| 头部到主要内容 | 16–20 px | 12–16 px |
| 内容到操作 | 16–20 px | 12–16 px |
| 信息量 | 一个主题，必要信息完整 | 一个重点 + 1–2 句摘要 |
| 高度 | 由内容决定 | 同排可以等高，不强制正方形裁字 |

这些仍是建议参数，不是原图测量值。缩小卡片时应重组内容，而不是连文字一起等比缩小。图二中的分段控件也只是局部交互，不是每个小卡片必须有的装饰。

### 材质与用色

- 页面底可从 `#F1F2F3` 起，卡片面从 `#FCFCFD` 起，局部抬升控件用 `#FFFFFF`。
- 使用第 5 节的轻投影；不画粗白框，不把所有边缘变成连续高光。
- 卡片可以完全没有彩色。若需要暖色、淡粉或淡紫，集中在局部并与白灰表面自然过渡。
- 真正可迁移的是完整表面、内部对齐、适度留白和浅层次，不是“白卡 + 彩色图表”。

### 图表明确排除在必选规范之外

不要求复现曲线、渐变填充、黑色浮标、月份刻度。未来图表按数据含义与可读性单独选择，只共享文字、中性色和层次语言。首页已取消的柱状图也不因这张参考而重新加入。

## 10. 组件状态与动效建议

以下是基于视觉方向提出的交互规范，**不是对静态参考图已有动画的描述**。

| 组件 | 默认 | 选中/展开 | 完成/异常 |
| --- | --- | --- | --- |
| 日期/筛选 | 浅色表面、中性文字 | 清晰的黑白反转；尺寸不跳动 | 事件点配可访问标签 |
| 分段控件 | 浅灰共同轨道 | 白色选中块，微弱接触阴影 | 状态切换有明确语义 |
| 信息行 | 无独立卡片，轻分隔 | 原位展开白色编辑面 | `✓ Saved` 或就近错误信息 |
| AI 入口 | 轻提示、小图标 | 在同一空间展开或打开底部弹层 | 显示来源，不用彩色光效代替回答 |
| 主按钮 | 深色面、白字 | 按下轻微明度变化 | 提交中禁重复操作并说明状态 |

动效起点：按下/高亮 120–160 ms；轻层次与内容切换 180–240 ms；信息展开或底部弹层 240–320 ms。以不超调的缓出为主。避免持续漂浮、呼吸光和明显回弹；尊重减少动态效果设置。

## 11. 一套风格，五种页面组织

下表用于未来适配，不表示本轮已授权实施。

| 页面 | 保持的信息结构 | 适合借用的风格手法 |
| --- | --- | --- |
| Home | 招呼语内 AI 入口、日期、左侧入住率与简短建议、右侧待处理 | 顶部少量暖雾；两块摘要明确分工；不恢复下方重复任务卡 |
| Work | 待确认、处理中、完成时间线 | 开放文字层级 + 必要审核面；黑色用在明确确认操作 |
| Analysis | 自己的经营表现、对比、解释与行动 | 中性数据画布和清楚文字层级；图表形式独立决定，不套用图二 |
| Explore | 周边需求、日历、价格光谱、话题、住宿轮播 | 局部更活跃的色彩和不同可视化；不复制 Analysis 的容器 |
| My Homestay | 民宿照片、连续信息行、原位编辑、文件审核 | 最安静的底色、分隔与浅编辑面；不改成卡片网格 |

统一应发生在字体、色彩角色、圆角尺度、控件状态、导航与层次强度。页面构图由任务决定，不用“每页放若干相同白卡”来证明统一。

## 13. 从零复现的顺序

1. 先画只有中性颜色的版式：标题、正文、分组、空白与导航。
2. 仅给确实需要边界的内容添加白色表面。
3. 确定一个主要焦点，并用黑白状态区分当前操作。
4. 添加浅阴影；只让必要控件出现轻微前后层次。
5. 选择一处氛围或数据色彩；同时出现时，让其中一处更克制。
6. 检查真实手机比例、中文长文本和所有状态，不按参考截图外框缩放 UI。
7. 最后再加入轻动效，不用动画修补静态层级问题。

## 14. 验收与走偏信号

### 复现成功

- 即使不显示品牌、照片与彩色图表，仍能认出统一的文字、空间和控件语言。
- 第一眼看到的是内容重点，随后才感到颜色与浅层次。
- 至少存在“开放内容”和“必要表面”两种组织方式。
- 导航选中态通过图标与文字表达，没有黑色选中底座。
- 图表颜色不干扰数值含义；数据出处和示例标注清楚。
- 320–430 px 宽下文字不被裁切；长内容增高，底部导航不遮挡操作。
- 正常正文对比度按至少 4.5:1 检查；关键控件边界和状态标记按至少 3:1 检查。浅色装饰不承担唯一的信息提示。
- 字号、触摸热区、键盘焦点和减少动态效果经过实际检查，不直接复制参考图里很浅很小的字。

### 已经走偏

- 所有卡片、按钮和导航都带白色发光轮廓：变成玻璃演示。
- 白灰元素都靠大双阴影挤出凹凸体积：变成重拟物。
- 每块表面都染粉紫、每个动作都发彩色光：失去中性主体。
- 每个功能都是同样的白色大圆角卡：把组件统一误当成页面统一。
- 主数据与标题全部粗黑：失去图二“轻数字、清晰主次”的节奏。
- 复制图二的加号或图一的任务筛选，却没有对应产品目的：复制了业务布局。
- 为了复现截图而把说明文字缩到真实手机难以读的尺寸：只适合展示图，不适合使用。

## 15. 交给无上下文设计者的简短任务书

> 为小型民宿经营者设计移动界面。采用中性灰白底、近白内容面、统一炭黑文字与有限浅阴影，形成安静的浅层次。图一参考页面氛围与圆润控件，图二参考小卡片的白灰层次、内部排版与颜色气质，不要求学习其图表。分组先依靠对齐与留白，必要时才使用白色容器。大面圆角约 26px，紧凑卡片 20–24px，输入约 20px。正文 15–16px，大标题约 30–36px，大数据数字较轻。彩色只用于局部氛围或有意义的内容，顶部可加入极淡暖色与紫色雾感。底部导航直接排列图标与文字，无整条胶囊底座，选中项为炭黑实心图标和加重标签，其余项为中灰线形图标和常规标签。保留现有业务与页面分工，不添加无用途的加号或恢复已删除组件。不做厚玻璃边、高光凸面、重拟物阴影或全屏彩色。本文为待确认研究方向，实际应用范围由用户另行指定。
